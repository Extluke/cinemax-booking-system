----------------------------------------------------------------------------------------------------

1.1 APA ITU CINEMAX BOOKING SYSTEM?
Cinemax Booking System adalah aplikasi berbasis web berskala enterprise yang dirancang khusus untuk 
mengotomatisasi seluruh proses operasional bioskop modern dan menyediakan pengalaman pemesanan tiket 
bioskop digital (online ticketing) secara real-time bagi penonton.

Aplikasi ini mengintegrasikan 3 pilar utama:
1. Platform Pelanggan (Public & Customer Portal): Menghadirkan katalog film interaktif, pemilihan 
   jadwal tayang dinamis, pemilihan denah kursi interaktif dengan ragam kelas kursi, checkout otomatis 
   dengan payment gateway Midtrans (QRIS, GoPay, Virtual Account, Kartu Kredit), penerbitan e-ticket 
   digital mandiri ber-QR Code, hingga fasilitas pengajuan pengembalian dana (refund) mandiri.
2. Sistem Operasional Staf/Kasir (Admin Portal): Menyediakan dasbor kontrol terpusat untuk memantau 
   transaksi, mengelola katalog film, mengontrol genre, merancang timeline jadwal tayang visual yang 
   mencegah bentrok jam pemutaran, mengatur layout ruangan dan kursi berbasis kuas (canvas brush), 
   menayangkan banner promo promosi, serta memverifikasi pengajuan refund.
3. Kontrol Manajerial & Keamanan (Super Admin Portal): Menyajikan analitik visual pendapatan 
   menggunakan grafik tren harian dan proporsi film (Chart.js), pemantauan jejak audit log keamanan 
   sistem real-time, manajemen otoritas akun staf, serta konfigurasi global bioskop (jam buka/tutup 
   harian, integrasi Midtrans Sandbox/Production, tarif pajak/layanan, batas waktu H- jam refund).

1.2 TATA CARA MENGGUNAKAN DAN MENJALANKAN APLIKASI
A. Prasyarat Sistem:
   - JDK (Java Development Kit) Versi 17 atau lebih baru terpasang di sistem.
   - MySQL Server (misalnya melalui XAMPP atau MySQL Community Server) aktif pada port 3306.
   - Peramban web modern (Google Chrome, Mozilla Firefox, Microsoft Edge, dll).

B. Langkah Menjalankan Server Aplikasi:
   1. Nyalakan modul MySQL pada XAMPP Control Panel.
   2. Buka phpMyAdmin (http://localhost/phpmyadmin) atau terminal MySQL, lalu buat database kosong:
      CREATE DATABASE cinemax_db;
   3. Pastikan konfigurasi database di `src/main/resources/application.properties` sudah sesuai:
      - server.port=8081
      - spring.datasource.url=jdbc:mysql://localhost:3306/cinemax_db?serverTimezone=Asia/Jakarta&useSSL=false
      - spring.datasource.username=root
      - spring.datasource.password=
      - spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect
   4. Buka terminal/PowerShell di direktori proyek Cinemax, lalu jalankan perintah:
      Windows    : .\mvnw.cmd spring-boot:run
      Linux/Mac  : ./mvnw spring-boot:run
   5. Tunggu hingga terminal memunculkan pesan "Started CinemaxApplication".
   6. Buka peramban dan akses: http://localhost:8081

C. Akun Bawaan (Default Dummy Accounts dari DataSeeder):
   Sistem secara otomatis menginisialisasi akun awal saat pertama kali dijalankan:
   - Akun Super Admin:
     * Email    : superadmin@cineplex.com
     * Password : superadmin123
     * Role     : ROLE_SUPER_ADMIN (Akses penuh seluruh fitur admin + sistem + laporan)
   - Akun Admin (Staf / Kasir):
     * Email    : admin@cineplex.com
     * Password : admin123
     * Role     : ROLE_ADMIN (Akses operasional: film, jadwal, studio, transaksi, refund, promo)
   - Akun Pelanggan (User):
     * Pengunjung umum dapat mendaftar mandiri melalui menu "Daftar" di halaman utama.

D. Alur Penggunaan (End-to-End User Flow):
   1. Alur Pelanggan (User):
      Buka Beranda -> Lihat Film Sedang Tayang / Buka Jelajah Film -> Klik Film -> Lihat Detail & Jadwal 
      -> Pilih Hari & Jam Tayang -> Pilih Kursi Bioskop -> Klik Lanjut Checkout -> Periksa Faktur 
      Ringkasan Pesanan -> Klik Bayar (Muncul Midtrans Snap Popup) -> Selesaikan Pembayaran -> 
      Buka Menu Tiket Saya -> Buka E-Tiket untuk melihat detail barcode & QR Code (dapat dicetak) -> 
      Jika ada halangan, ajukan refund sebelum batas waktu H- jam penayangan.
   2. Alur Staf / Admin:
      Masuk dengan email staf -> Masuk ke Dashboard Admin -> Pantau okupansi studio & transaksi harian -> 
      Kelola data film & unggah poster potret -> Atur jadwal tayang pada matriks waktu studio -> 
      Tinjau data transaksi penjualan -> Proses pengajuan refund dari pelanggan (setujui / tolak).
   3. Alur Super Admin:
      Masuk dengan email Super Admin -> Pantau Laporan Analitik Pendapatan & Grafik Penjualan -> 
      Kelola akun staf (tambah/hapus hak akses) -> Pantau Audit Log atas seluruh aktivitas sistem -> 
      Sesuaikan konfigurasi bioskop (nama, alamat, jam operasional hari kerja/akhir pekan, kunci Midtrans, 
      kebijakan potongan biaya refund).

5. HALAMAN PILIH KURSI (SEAT LAYOUT & REAL-TIME SELECTION)
   URL Endpoint: GET `/pilih-kursi?jadwalId={jadwalId}`
   Template    : `src/main/resources/templates/pilih_kursi.html`
   Akses       : Wajib Login (`ROLE_USER`, `ROLE_ADMIN`, `ROLE_SUPER_ADMIN`)
   Rincian Fitur:
   - Indikator Langkah Pesanan: Lencana "Langkah 2/3" sebagai penunjuk alur pemesanan.
   - Header Ringkasan Jadwal: Menampilkan judul film, nama studio, tipe studio, serta tanggal dan 
     jam tayang yang dipilih.
   - Canvas Denah Kursi Interaktif:
     * Representasi visual "LAYAR BIOSKOP" di bagian atas denah.
     * Grid kursi yang dipetakan sesuai matriks baris (A, B, C, ...) dan kolom (1, 2, 3, ...).
     * Dukungan visual lorong / jalan setapak (walkway) yang tidak dapat diklik.
     * Dukungan variasi kelas kursi:
       - Kursi Reguler standar.
       - Kursi Sweetbox (kursi berpasangan dengan span kolom 2).
       - Kursi Premiere / VIP.
     * Status visual kursi:
       - Kursi Tersedia (Available): Dapat diklik dan dipilih oleh pengguna.
       - Kursi Terisi (Occupied): Berwarna abu-abu, nonaktif, dan tidak dapat dipilih karena telah 
         dipesan orang lain.
       - Kursi Terpilih (Selected): Berubah warna menjadi warna primer bioskop saat dipilih.
   - Fitur Geser Horizontal (Horizontal Scroll Hint) untuk kenyamanan tampilan di smartphone.
   - Sticky Bottom Checkout Bar:
     * Legenda warna kursi (Reguler, Sweetbox, Premiere, Terisi, Dipilih).
     * Indikator penghitung waktu mundur transaksi (Countdown timer).
     * Penghitungan total harga bayar secara dinamis dan real-time sesuai jumlah kursi yang diklik 
       menggunakan format mata uang Rupiah (IDR).
     * Tombol "Lanjut Checkout ->" dengan indikator status loading "Memproses...".
   - Proteksi Keamanan Backend pada Pemilihan Kursi:
     * Pengiriman data via AJAX POST ke `/api/payment/checkout` disertai X-CSRF-TOKEN.
     * Proteksi Race Condition & Double Booking: Sistem memverifikasi kembali status ketersediaan kursi 
       di database tepat sebelum token transaksi diterbitkan. Jika ada pengguna lain yang memesan 
       kursi tersebut selang beberapa milidetik sebelumnya, sistem otomatis menolak dan memunculkan 
       peringatan ramah.
     * Proteksi IDOR (Insecure Direct Object Reference): Sistem mengabaikan manipulasi ID pengguna dari 
       request payload dan selalu mengikat transaksi ke email pengguna yang sedang login di Spring Security.

   Template    : `src/main/resources/templates/faktur_pesanan.html`
   Akses       : Wajib Login
   Rincian Fitur:
   - Indikator Langkah: Lencana "Langkah 3/3" (Menunggu Pembayaran).
   - Kotak Pengingat Batas Waktu Bayar:

   - Rincian Lengkap Faktur Pesanan:
     * Nomor Pesanan / Order ID unik (format: ORDER-XXXXXXXX).
     * Judul film yang dipesan.
     * Jadwal tayang (Hari, Tanggal, Bulan, Tahun, Jam WIB).
     * Nama Studio beserta Tipe Studio penayangan.
     * Rincian nomor kursi yang berhasil dipesan beserta total kuantitas tiket (misal: "A7, A8 (2 Tiket)").
     * Breakdown perhitungan harga: [Jumlah Tiket] x [Harga Satuan] = [Subtotal Tiket].
     * Total Nominal Pembayaran Akhir yang ditonjolkan secara jelas.
   - Integrasi Midtrans Snap Payment Gateway:
     * Pemuatan script Midtrans Snap JS secara dinamis (otomatis menyesuaikan lingkungan Sandbox 
       atau Production berdasarkan konfigurasi bioskop).
     * Tombol interaktif "Bayar Sekarang dengan Payment Gateway ->" yang memicu popup modal Midtrans Snap.
     * Mendukung multi-channel pembayaran: QRIS (GoPay, OVO, Dana, LinkAja), Virtual Account Bank 
       (BCA, Mandiri, BNI, BRI, Permata), Kartu Kredit/Debit, dan gerai retail.

       - onSuccess: Pengguna otomatis dialihkan ke halaman "Tiket Saya".
       - onPending: Notifikasi instruksi penyelesaian tagihan tertunda.
       - onError: Notifikasi kegagalan pembayaran.
       - onClose: Notifikasi peringatan saat pengguna menutup jendela sebelum transaksi selesai.
   - Tombol Navigasi Alternatif "Ubah Kursi" untuk kembali ke denah pemilihan jika berubah pikiran.

    - Mekanisme Persetujuan Refund 3 Tahap (Three-Phase Refund Workflow):
      * Tahap 1 - Peninjauan (PENDING):
        - Tombol "Approve": Admin menyetujui refund. Begitu disetujui, sistem secara otomatis melepaskan 
          kursi bioskop yang sebelumnya terkunci sehingga kursi tersebut kembali tersedia dan dapat dibeli 
          oleh pelanggan lain di website.

          dan alasan penolakan dapat dibaca pelanggan di e-tiketnya.
      * Tahap 2 - Persetujuan (APPROVED): Pengajuan telah disetujui staf dan menunggu bagian keuangan 
        mentransfer dana pengembalian.
      * Tahap 3 - Penyelesaian (PROCESSED):
        - Tombol "Lanjutkan": Admin menandai bahwa dana pengembalian telah berhasil ditransfer ke rekening 
          pelanggan. Status transaksi berubah menjadi REFUNDED penuh.

   - Grafik Tren Pendapatan Harian (Daily Revenue Line Chart):
     * Grafik garis interaktif (Chart.js) yang memetakan fluktuasi pendapatan dari hari ke hari secara visual.
     * Titik koordinat menyajikan nilai nominal pendapatan harian secara presisi saat kursor diarahkan.
   - Grafik Proporsi Kontribusi Film (Film Revenue Contribution Doughnut Chart):
     * Grafik donat interaktif (Chart.js) yang memvisualisasikan persentase kontribusi penjualan tiket 
       dari masing-masing judul film bioskop.
     * Mempermudah manajemen dalam menentukan film terlaris (Box Office) dan film yang kurang diminati penonton.

     * Menyajikan matriks komparasi judul film dan total nominal pemasukan yang dihasilkan oleh film tersebut.

   - Penghapusan Akun Staf:

     * Proteksi Anti Self-Delete: Akun Super Admin yang sedang login tidak dapat menghapus akunnya

   - Pembaruan Profil Administrator Utama:

   - Pembaruan Kata Sandi Administrator:
     * Verifikasi kata sandi lama dan input kata sandi baru minimal 8 karakter unik.
   - Konfigurasi Identitas & Cabang Bioskop:
     * Nama Bioskop: Nama yang akan tampil pada seluruh logo, kop tiket, judul halaman, dan invoice.
     * Alamat Bioskop: Lokasi fisik cabang bioskop.
     * Kontak Customer Service: Nomor WhatsApp atau email bantuan pelanggan.
     * Tautan Sematan Google Maps (Google Maps Embed URL): Mendukung tautan langsung, URL embed, 
       maupun tag `<iframe>` yang otomatis diformat sistem untuk dirender di Beranda.
   - Konfigurasi Jam Operasional Harian (Per-Day Operating Hours Matrix):
     * Konfigurasi mandiri untuk 7 hari dalam sepekan (Senin, Selasa, Rabu, Kamis, Jumat, Sabtu, Minggu).
     * Sakelar Toggle Buka/Tutup: Jika sakelar dimatikan pada hari tertentu (misal: bioskop tutup), 
       sistem otomatis melarang penerbitan jadwal tayang pada hari tersebut.
     * Jam Mulai & Jam Selesai: Mengatur rentang jam buka operasional per hari (misal Senin: 10:00 - 22:00, 
       Sabtu: 08:00 - 24:00). Matriks jadwal tayang akan otomatis menyesuaikan skala jam ini.
   - Konfigurasi Provider Payment Gateway Midtrans:
     * Pilihan Environment: Beralih instan antara mode "Sandbox (Testing)" dan mode "Production (Live)".
     * Client Key: Kunci publik Midtrans yang diinjeksikan ke script Snap frontend.
     * Server Key: Kunci rahasia Midtrans untuk otentikasi API backend.
     * Proteksi Sensor Kredensial: Di halaman pengaturan, Server Key dan Client Key disensor dengan 
       bintang (`********`) agar tidak dapat diintip oleh pihak yang tidak bertanggung jawab.
   - Konfigurasi Biaya & Transaksi Bioskop:
     * Tarif Pajak / PPN (%): Persentase pajak transaksi tiket.
     * Biaya Layanan (Platform Fee Rp): Nominal biaya administrasi per transaksi.
     * Maksimal Tiket per Transaksi: Pembatasan kuota pembelian tiket per checkout guna mencegah penimbunan oleh calo.
   - Kebijakan Pengembalian Dana (Refund Policy Global):
     * Batas Waktu Pengajuan Refund (Jam sebelum tayang): Menentukan toleransi H- berapa jam tiket boleh 
       di-refund oleh pelanggan (default 2 jam sebelum film dimulai).
     * Potongan Saldo Refund (%): Menentukan persentase potongan administrasi refund (misal potongan 20% 
       berarti pelanggan menerima pengembalian sebesar 80% dari total yang dibayarkan).


====================================================================================================
BAGIAN 3: CATATAN KEAMANAN & ARSITEKTUR TEKNIS UNGGULAN
====================================================================================================

1. Proteksi Privilege Escalation:
   Rute manajerial `/admin/pengaturan/**`, `/admin/staf/**`, `/admin/audit-log/**`, dan `/admin/laporan/**` 
   dikunci secara ketat hanya untuk `ROLE_SUPER_ADMIN` baik di tingkat Security Filter Chain maupun 
   anotasi `@PreAuthorize`.
2. Proteksi Insecure Direct Object Reference (IDOR):
   Seluruh transaksi dan tiket hanya dapat diakses atau diajukan refund oleh pemilik akun yang sah 
   berdasarkan session otentikasi Spring Security.
3. Proteksi Race Condition & Double Booking:
   Validasi ganda ketersediaan kursi (`isSeatBooked`) dijalankan secara atomik sebelum transaksi dibuat, 
   menjamin tidak akan pernah ada dua penonton yang mendapatkan kursi yang sama pada satu jadwal.
4. Validasi Keamanan Unggah Berkas Poster (Anti-Web Shell):
   Pemeriksaan MIME-type file poster, batas ukuran maksimal 2MB, sanitasi nama file menjadi UUID acak, 
   serta validasi rasio potret 2:3.
5. Verifikasi Integritas Webhook Payment (SHA-512 Signature):
   Webhook notifikasi pembayaran dari Midtrans diverifikasi menggunakan hash kriptografi SHA-512 
   dengan Server Key rahasia sebelum sistem mengubah status transaksi menjadi sukses (lunas).
6. Port Standar:
   Aplikasi selalu berjalan pada port 8081 guna menghindari konflik port dengan server lokal XAMPP (Apache 8080/80).
